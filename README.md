# NEW_PROJECT_CHEATSHEET — промпты и инструкции для ИИ-агентов

Набор инструкций для создания и развития проектов: от обсуждения идеи до проверенного результата, документации и Git-коммита. Он задаёт единый порядок работы агента и переносит общие правила в конкретный проект.

Работу выполняет ИИ-агент с доступом к файлам и нужным инструментам. Сам набор не является автономным сервисом: скрипты синхронизируют инструкции и проверяют этот перенос, но не создают приложение, не выполняют весь план и не переключают модели автоматически.

## Что задают инструкции

- Обсуждение цели, ограничений и существенных решений до создания нового проекта.
- Пошаговый план в Obsidian, критерии приёмки и актуальные статусы работы.
- Выбор технологий с учётом уже известных предпочтений; Rust по умолчанию для новых программных проектов, если владелец явно не выбрал другой язык.
- Минимум три роли для исходной задачи. У каждого координатора ровно два прямых подчинённых, у рабочего ноль. Перед началом работы координатор показывает текстовое дерево с числом агентов и поручением каждой роли и ждёт явного подтверждения пользователя.
- Выбор моделей в диапазоне Terra–Astra с усилием `xhigh`; создание и содержательную оценку промптов, инструкций и шаблонов исключительно на Astra / `xhigh`.
- Защиту данных и пользовательских записей, проверки безопасности, оптимизации и интерфейса в применимых задачах.
- Ведение русской документации, идей, ошибок, отложенных вопросов и ссылок сайта.
- Итоговую проверку, коммит относящихся к задаче изменений и отправку в настроенный удалённый репозиторий.

Это требования к процессу, а не гарантия безопасности, качества или экономии токенов. Доступность моделей и инструментов проверяется в рабочей среде. Полные правила находятся в главной шпаргалке; этот README — краткий обзор.

## Как начать

Передайте агенту задачу и доступ к главному шаблону. Например:

```text
Создай [описание проекта] по NEW_PROJECT_CHEATSHEET.
Сначала прочитай главную шпаргалку, реестр технологий и рекомендации.
Разбери цель и существенные решения. Покажи дерево в блоке Markdown с меткой text.
В заголовке укажи число агентов, под каждой ролью — её задачи и результат.
Дождись моего явного подтверждения состава и иерархии, затем приступай к работе.
Подготовь .obsidian/PROJECT_CREATION_PLAN.md до реализации
и выполняй согласованный план с предусмотренными проверками.
```

Для запуска скриптов нужны PowerShell 7, Git и доступ к исходным файлам шаблона; сам шаблон также должен оставаться Git-репозиторием. Синхронизацию выполняют из корня другого, уже созданного Git-репозитория проекта:

```powershell
& 'D:\projects\NEW_PROJECT_CHEATSHEET\scripts\sync-template-instructions.ps1' -ProjectRoot (Get-Location)
```

`SYNC_RESULT=UPDATED` означает обновление блоков, `SYNC_RESULT=CURRENT` — их актуальность. После успешного запуска агент читает актуальные проектные инструкции; при ошибке сначала устраняет её причину. Сам главный шаблон с собой не синхронизируют.

Проверить механизм переноса можно из корня репозитория шаблона:

```powershell
& .\scripts\test-template-sync.ps1
```

## Что появляется в целевом проекте

Скрипт обслуживает ровно пять файлов. Если файл отсутствует, создаётся файл с управляемым блоком; существующий текст вне блока сохраняется.

| Файл в целевом проекте | Для чего используется |
| --- | --- |
| `AGENTS.md` | Действующие инструкции для агента. |
| `PREFERENCES.md` | Предпочтения и правила работы с проектом. |
| `.obsidian/PROJECT_CREATION_PLAN.md` | План создания, этапы и результаты. |
| `.obsidian/SECURITY_CHECKLIST.md` | Проверки безопасности. |
| `.obsidian/FINAL_VERIFICATION_CHECKLIST.md` | Итоговая проверка перед выпуском. |

В блоки входят главные правила и снимки реестра технологий и рекомендаций. Содержимое истории запусков туда не переносится. Синхронизация не заполняет фактический план и результаты проверок за агента.

Остальную документацию агент ведёт отдельно: описание проекта, `CHANGELOG.md` и `STRUCTURED_IDEAS.md` в Obsidian, `LINKS.md` для сайта, а при отложенных вопросах — `.obsidian/DEFERRED_ISSUES.md`.

`HANDWRITTEN_IDEAS.md` и пользовательские записи в `BUGS.md` и журнале отложенных вопросов остаются неприкосновенными. Результаты по ним оформляются отдельно по правилам шпаргалки; пользовательский текст не переписывается.

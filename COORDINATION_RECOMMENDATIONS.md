Версия: 2026-11-25, начальная. Основание — прямые требования владельца к координации, выбору моделей и экономному обмену контекстом. Сопоставимых завершённых запусков с измерениями пока нет; оптимальное число агентов, экономия токенов, стоимости и времени не доказаны. Обязательные правила находятся в `NEW_PROJECT_CHEATSHEET.md`; рекомендации помогают применить их к конкретной задаче.

## Как составлять дерево

1. Начать с трёх ролей для одной исходной задачи: координатор и два исполнителя с отдельными проверяемыми результатами. Для небольшой работы вторым результатом может быть самостоятельная проверка конкретного риска; не создавать фиктивную проверку ради числа ролей. Использовать готовое дерево при уточнениях и продолжении той же задачи.
2. Дополнительную роль обосновывать независимым результатом и стоимостью передачи контекста. Сначала проверить, можно ли поручить этот блок уже существующей роли. Для каждого обычного координатора сохранять предел в два прямых подчинённых; расширять верхние уровни только при реальном управлении самостоятельными подкоординаторами.
3. До запуска показать дерево, количество, назначение ролей, модели и `xhigh`. При доступности использовать подагентов, чаты оставить запасным механизмом. Проверить лимит среды; при нехватке слотов использовать волны, не увеличивая число ролей для имитации параллельности.
4. Выбирать модель по содержанию блока в диапазоне Terra–Astra и проверять её доступность. Начальная схема: Terra / `xhigh` для штатного деплоя и обычной реализации по готовому процессу, Sol / `xhigh` для более сложного технического согласования, Astra / `xhigh` для идей и неоднозначных решений. Промпты, инструкции и проектные шаблоны требуют автора и финальной содержательной оценки исключительно Astra / `xhigh`.
5. Передавать ограниченное поручение: цель, нужные источники, границы файлов, зависимости, критерии приёмки. Возвращать краткий результат с проверками и артефактами. Сначала согласовать владельца каждого файла; полную историю передавать только при объяснимой необходимости.

## Что измерять

В `COORDINATION_HISTORY.md` записывать доступные факты о качестве, переработках, контексте, токенах, стоимости и длительности, обязательно с источником и охватом измерений. Отсутствующие данные обозначать «неизвестно». Снижение стоимости отдельного вызова не означает уменьшение токенов или длительности всей задачи.

Дополнительные агенты могут увеличить потребление токенов; для последовательных зависимостей и частых записей в общее состояние выигрыш может отсутствовать. Это общий риск, описанный в [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/responses-multi-agent), проверенной 2026-11-25. Он не является измерением текущей команды и не отменяет установленный владельцем минимум из трёх ролей.

## Когда менять рекомендации

Только по отдельной прямой просьбе владельца; новые логи, очередной запуск и синхронизация не дают такого разрешения. Автор изменений и финальный содержательный проверяющий — Astra / `xhigh`. Скрипт лишь переносит готовый снимок в проекты и не меняет этот файл.

При разрешённом пересмотре для каждого вывода записать:

- дату и изменённую рекомендацию;
- нейтральные идентификаторы использованных записей истории;
- сопоставимость задач: объём, критерии качества, инструменты, модели и границы измерения;
- измерения и их источник, включая неполные или неизвестные значения;
- уверенность, ограничения и случаи, к которым вывод не относится.

Текущая уверенность: высокая в точности отражения пользовательских требований; эмпирическая эффективность этой схемы пока не установлена. Начальная запись `RUN-2026-11-25-01` описывает внедрение правил, но сама по себе не доказывает оптимальность команды.
